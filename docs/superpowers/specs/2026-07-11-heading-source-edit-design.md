# 标题源码编辑交互设计

## 目标

让 Markdown 标题在进入编辑状态时显示并允许直接编辑完整的 ATX 源码，例如 `### 标题内容`；当标题失去焦点后，再恢复为 Markdown 渲染效果。

## 交互

- 未编辑时，标题按当前级别渲染为 `h1` 至 `h6`，不显示井号。
- 用户点击标题行时，该行切换为源码编辑状态，显示对应数量的 `#`、一个空格和标题内容。
- 源码中的井号和空格可以像普通文本一样定位光标、插入和删除。
- 用户点击编辑器中的其他位置，使当前标题失去焦点时，提交源码并恢复渲染。
- 一至六个井号加空格解析为对应级别标题。
- 删除全部井号后，内容解析为普通段落。
- 超过六个井号或不符合标题语法的内容按普通段落处理，避免产生无效标题节点。

## 实现边界

使用标题 NodeView 管理单个标题的“渲染态”和“源码编辑态”。源码编辑态使用独立文本输入区域，提交时通过 ProseMirror transaction 将源码解析为标题或段落节点。这样井号是真正可编辑的输入内容，同时不需要把 Markdown 标记永久写入 ProseMirror 标题节点。

现有标题装饰 widget 不再负责标题源码展示，以免出现重复井号。行内强调、链接、引用等现有语法揭示行为保持不变。

## 状态与数据流

1. NodeView 从标题节点的 `level` 和 `textContent` 生成源码文本。
2. 点击标题后进入编辑态，并将浏览器焦点放入源码输入区域。
3. 用户直接修改源码。
4. 输入区域失焦时解析源码：匹配 `^(#{1,6})\\s+(.*)$` 时生成对应标题，否则生成段落。
5. transaction 替换原节点，并保持编辑器文档、撤销历史和保存序列化同步。

## 键盘和焦点

- 源码输入区域采用浏览器原生文本编辑行为，允许在井号前后自由移动光标。
- `Enter` 提交当前标题，并将光标移动到后续正文位置。
- `Escape` 放弃未提交修改并恢复渲染态。
- 普通失焦提交修改。

## 验证

- H1 至 H6 点击后分别显示正确数量的井号。
- 将 `## 标题` 改为 `### 标题`，失焦后渲染为 H3，保存结果为 `### 标题`。
- 删除井号，失焦后变为普通段落且文本不丢失。
- 删除或追加井号后可撤销、重做。
- 点击其他标题可正确提交前一个标题并编辑新标题。
- 行内 Markdown、引用块和其他编辑器功能无回归。
