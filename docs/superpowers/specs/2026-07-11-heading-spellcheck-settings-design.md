# 标题退格、拼写检查与界面状态持久化设计

## 1. 目标

本次改动包含三个相互关联但边界清晰的目标：

1. 修复 Markdown 标题语法揭示区域的光标与退格行为，使用户在标题正文开头按 Backspace 时能够像删除真实 `#` 一样逐级降低标题等级。
2. 在状态栏字数统计左侧增加拼写检查按钮，提供自动语言检测、关闭拼写检查和手动选择具体语言的菜单。
3. 持久化拼写检查设置与侧边栏展开/收起状态，并在应用重新启动后恢复。

不改变 Markdown 的结构化存储原则：标题继续以 ProseMirror `heading` 节点保存，揭示出的 `#` 仍然是装饰组件，不写入文档正文。

## 2. 标题退格与左箭头行为

### 2.1 根因

当前标题前缀由 `syntaxReveal.ts` 创建为 `contenteditable=false` 的 ProseMirror widget。它只负责视觉展示，不占用 ProseMirror 文档位置。因此：

- 浏览器可以短暂把原生 DOM 选区绘制到 widget 附近，但 ProseMirror 随后会把选区归一化回正文开头，产生左箭头“跳过去又闪回来”的现象。
- Backspace 无法删除 widget 中的 `#`，因为它不是可编辑文档文本。
- ProseMirror 默认 Backspace 命令也不知道“删除一个虚拟 `#`”应当对应降低标题等级。

### 2.2 目标行为

当选区为空、光标位于标题正文最前面时，Backspace 执行以下转换：

| 当前块 | Backspace 后 |
| --- | --- |
| H6 | H5 |
| H5 | H4 |
| H4 | H3 |
| H3 | H2 |
| H2 | H1 |
| H1 | 普通段落 |

转换保留标题中的所有文字和行内标记，光标保持在块内容开头。每次转换都是独立 transaction，可通过撤销逐级恢复。

当光标已经位于标题正文开头时，左箭头不再尝试把原生 DOM 选区放入虚拟前缀。编辑器消费该按键并保持 ProseMirror 选区不变，从而避免闪烁。左箭头不会修改标题等级；只有 Backspace 执行等级转换。

### 2.3 命令边界

标题降级命令只在以下条件同时成立时生效：

- 选区为空。
- 当前父节点是 `heading`。
- `$from.parentOffset === 0`。

其余位置继续交给现有 ProseMirror keymap。该命令注册在 `baseKeymap` 之前，确保命中特定场景时优先执行；没有命中时返回 `false`，不改变其他 Backspace 行为。

## 3. 拼写检查菜单

### 3.1 状态栏入口

在右下角字数统计左侧增加拼写检查按钮。按钮使用紧凑文字或图标加文字呈现，并提供描述当前模式的 `aria-label` 和 `title`。

状态栏右侧顺序为：

1. 拼写检查按钮。
2. 字数统计。

自动模式下，按钮提示信息包含最近一次可靠识别出的语言。

### 3.2 菜单布局

菜单采用用户确认的参考图式布局：

1. 顶部搜索框，按本地化语言名称和语言代码过滤。
2. 第一组选项：
   - 自动检测语言。
   - 不使用拼写检查。
3. 分隔线。
4. 可滚动的具体语言列表。

具体语言列表来自 Electron 当前 session 的 `availableSpellCheckerLanguages`，不维护一份与运行平台脱节的固定列表。每项左侧显示通过 `Intl.DisplayNames` 本地化的语言名称，右侧显示规范化的大写代码，例如 `EN-US`、`EN-GB`、`ZH-CN`、`JA`。无法本地化时直接显示原始语言代码。

菜单使用单选语义；当前选项显示勾选状态。点击按钮切换菜单，点击菜单外部或按 Escape 关闭。搜索框和选项支持键盘聚焦，选择后立即应用并关闭菜单。

## 4. 自动语言检测

### 4.1 检测依赖

安装并使用 `franc-min`。该包是纯 JavaScript、ESM-only 的语言检测库，支持 82 种常见语言，并返回 ISO 639-3 三字母代码。

应用内维护一个明确的 ISO 639-3 到基础 BCP 47 语言代码映射。映射只负责把检测结果转换为 Electron 词典匹配入口，例如：

- `eng` → `en`
- `cmn` → `zh`
- `jpn` → `ja`
- `deu` → `de`

### 4.2 检测输入与调度

检测输入从当前 ProseMirror 文档提取纯文本，不读取序列化后的 Markdown 标记。文档变化后使用防抖调度检测，避免每次按键都调用语言识别和切换词典。

自动检测只在拼写模式为 `auto` 时运行。手动语言和关闭模式不执行检测。

### 4.3 从基础语言选择具体词典

语言检测通常只能确定基础语言，不能可靠判断 `en-US` 与 `en-GB` 等地区变体。应用按以下优先级从 Electron 实际可用词典中选择：

1. 与基础语言匹配、同时也匹配操作系统首选 locale 的词典。
2. 当前已启用且基础语言匹配的词典。
3. Electron 可用列表中第一个基础语言匹配项。

如果检测出的基础语言没有可用词典，则不切换到无关语言。

### 4.4 不确定结果与回退

以下情况视为没有可靠的新结果：

- 文本短于检测所需的最小有效长度。
- `franc-min` 返回未知语言。
- 第一候选与后续候选无法形成足够明确的领先差距。
- 检测语言无法映射到 Electron 可用词典。
- 检测过程抛出异常。

此时继续使用上一次可靠检测结果。应用启动后尚无可靠结果时，使用 Electron 当前词典或操作系统首选 locale 对应词典作为回退。

自动模式菜单项右侧显示当前实际使用的语言，例如“英语 · EN-US”。该值表示当前词典，而不是声称检测器能够确定地区变体。

## 5. Electron 拼写检查控制

拼写检查由主进程控制当前窗口 `webContents.session`：

- `auto`：启用内置拼写检查，并应用自动检测选出的具体词典。
- `off`：调用 Electron API 禁用内置拼写检查。
- `language`：启用内置拼写检查，并应用用户选择的单个语言代码。

主进程通过 IPC 向渲染进程提供：

- 当前拼写设置。
- 当前实际使用语言。
- 当前平台可用语言列表。
- 更新拼写模式或自动检测结果的方法。

主进程验证渲染进程提交的语言代码确实存在于 `availableSpellCheckerLanguages` 中。无效值不会传给 Electron API，而是保留现有有效设置并返回规范化状态。

## 6. 设置持久化

### 6.1 设置结构

现有 `ThemeManager` 已经在 Electron `app.getPath('userData')/settings.json` 中保存主题字段。本次不能新增另一个独立写入器，否则主题更新和拼写/侧边栏更新会互相覆盖。应用改为由一个集中式设置管理器独占读写现有文件，并保持已有主题字段位于顶层，以兼容用户当前的设置文件。

完整设置至少包含：

```ts
interface AppSettings extends ThemeSettings {
  spellcheck: {
    mode: 'auto' | 'off' | 'language'
    language: string | null
    detectedLanguage: string | null
  }
  sidebarVisible: boolean
}
```

`language` 只在手动模式下代表用户选择；`detectedLanguage` 保存自动模式最近一次可靠使用的具体 Electron 词典代码。

旧版设置文件中的 `themeMode`、`manualTheme`、`dayTheme` 和 `nightTheme` 字段保持原名、原层级和原语义。首次加载旧文件时，只补充缺失的 `spellcheck` 与 `sidebarVisible` 默认值。

### 6.2 读取、合并与写入

启动时读取设置文件，并与默认值进行字段级合并。缺失字段使用默认值；类型错误或不受支持的语言代码被规范化为安全默认值。文件不存在或 JSON 损坏时不阻止应用启动。

设置更新采用单一主进程设置管理器串行写入，主题管理器也通过它读取和更新主题字段，避免主题、拼写设置和侧边栏设置并发更新时互相覆盖。写入失败不会中断编辑器；当前会话继续使用内存状态，并在开发日志中记录错误。

默认值为：

- 拼写模式：`auto`。
- 手动语言：`null`。
- 最近检测语言：Electron 当前词典或系统 locale 匹配项。
- 侧边栏：收起，与当前应用默认行为一致。

### 6.3 侧边栏范围

本次只持久化侧边栏展开/收起状态。侧边栏内部“文件/大纲”页签仍在每次启动时默认选择“文件”，不持久化当前页签。

## 7. 组件边界与数据流

### 7.1 主进程

新增集中式设置管理器，负责：

- 加载、校验和保存设置。
- 保存现有主题字段，并为 `ThemeManager` 提供主题设置读写接口。
- 查询 Electron 可用拼写语言。
- 应用 `spellCheckerEnabled` 与具体词典。
- 处理来自渲染进程的设置更新。

`ThemeManager` 继续负责主题文件、系统明暗监听和有效主题计算，但不再直接读写 `settings.json`。

### 7.2 Preload

通过 context-isolated API 暴露最小接口，不向渲染进程直接暴露 Electron session：

- 获取设置快照。
- 更新拼写模式。
- 提交自动检测结果。
- 更新侧边栏可见状态。
- 订阅主进程规范化后的设置变化。

### 7.3 渲染进程

- `App` 从设置快照初始化侧边栏状态，并在切换时持久化。
- `StatusBar` 管理拼写菜单的展示和用户操作。
- 独立的语言检测模块从当前 ProseMirror 文档提取文本、调用 `franc-min`、做可靠性判断并提交基础语言结果。
- 主进程返回规范化后的具体词典代码，渲染进程用它更新菜单勾选和提示文本。

## 8. 测试与验证

### 8.1 标题行为

- H1 至 H6 在正文开头按 Backspace 时按表格逐级转换。
- H1 转普通段落后保留文字和行内标记。
- 非标题、非块首、非空选区不触发标题降级命令。
- 连续撤销按相反顺序恢复标题级别。
- Markdown 序列化输出与最终节点等级一致。
- 标题正文开头按左箭头时选区稳定，无 DOM 光标闪烁到 widget 前方。

### 8.2 拼写检查

- 菜单显示 Electron 返回的语言并支持按名称、代码搜索。
- 自动、关闭、手动语言三种模式互斥并即时应用。
- 英文、中文、日文样本文本能映射到相应基础语言。
- 地区变体按系统偏好选择；无偏好时使用稳定的可用列表回退。
- 短文本、未知语言、无对应词典和检测异常保留上一次可靠语言。
- 自动检测经过防抖，不会在每次 transaction 上立即调用主进程。

### 8.3 持久化与回归

- 重启后恢复拼写模式、手动语言或最近自动语言。
- 重启后恢复侧边栏展开/收起状态。
- 损坏或旧版设置文件能够回退到默认值。
- 旧版主题设置在首次加载和后续拼写/侧边栏更新后保持不变。
- 文件打开、编辑、保存、主题切换、字数统计和侧边栏页签不受影响。
- 运行 ESLint、TypeScript 类型检查和生产构建。

## 9. 非目标

- 不修改 Markdown 解析或序列化格式。
- 不把语法揭示 widget 改成真实文本。
- 不提供多语言同时启用模式；手动模式一次选择一个具体词典。
- 不持久化侧边栏当前“文件/大纲”页签。
- 不实现自定义拼写词典、忽略单词或右键拼写建议菜单。
- 不声称语言检测器能够可靠确定英语等语言的地区变体。
