# Lume 单文档编辑模式设计

## 目标

移除编辑页面顶部的多标签栏，将 Lume 从多标签文档编辑器改为单文档编辑器。同一时间只加载、编辑和保存一个 Markdown 文件，同时继续支持工作区文件树、大纲、字数统计、拖放和未保存内容保护。

## 用户体验

### 单文件打开

- 任意时刻最多只有一个当前文档。
- 从文件树、打开文件对话框、应用菜单或拖放操作选择新文件时，使用同一套文档替换流程。
- 当前文档没有未保存修改时，直接读取并打开目标文件。
- 当前文档有未保存修改时，先自动保存当前文档；保存成功后再打开目标文件。
- 自动保存失败时显示“自动保存失败，请手动保存后再进行操作”，保留当前文档及其编辑状态，并取消本次打开或切换操作。
- 再次选择当前已经打开的文件时不重新读取文件，也不触发保存或替换。

### 拖入文件与文件夹

- 一次拖入多个 Markdown 文件时，左侧文件列表展示所有可用的拖入文件，但编辑区只打开其中第一个文件。
- 拖入文件夹时，左侧文件列表继续展示该文件夹内扫描到的 Markdown 文件，编辑区打开返回列表中的第一个文件。
- 如果拖入内容同时产生工作区文件树和多个 Markdown 文件，先更新文件树，再执行单文档打开流程。
- “第一个文件”使用主进程返回的稳定顺序，不额外按名称重新排序。

### 文件名与布局

- 删除编辑区顶部的标签栏，不保留空白占位高度。
- 当前 Markdown 文件名显示在 Electron 窗口最顶部的系统标题栏区域，而不是渲染页面或编辑区内部。
- 标题栏使用 `titleBarStyle: 'hidden'` 与 `titleBarOverlay`：渲染层绘制居中标题，系统继续提供原生最小化、最大化和关闭按钮。
- 没有当前文档时，标题栏中间显示应用名 `Lume`。
- 文件名过长时使用单行省略，且不得遮挡或挤压右侧原生窗口控制按钮。
- 标题栏空白区域可拖动窗口；文件名不提供标签切换或关闭交互。
- 深浅主题变化时同步标题栏 overlay 的背景色与按钮符号颜色。
- 未保存状态不再依赖标签上的圆点；文件名展示区域不新增 dirty 标记。

## 状态模型

工作区状态从多标签模型：

```ts
tabs: Tab[]
activeTabId: string | null
```

改为单文档模型：

```ts
document: WorkspaceDocument | null
```

`WorkspaceDocument` 持有：

- `filePath`
- `title`
- `dirty`
- `editorState`

不保留只有一个元素的标签数组，也不保留活动标签 ID。打开、保存、编辑器事务、大纲和字数统计都直接读写唯一的当前文档。

## 组件与数据流

### 工作区 Store

Store 负责集中实现目标文件替换流程，避免不同入口各自处理自动保存：

1. 判断目标路径是否等于当前文档路径。
2. 若当前文档为 dirty，尝试保存。
3. 保存失败时提示用户并终止操作。
4. 读取目标文件并创建新的 `EditorState`。
5. 使用新文档原子替换当前文档。

手动保存仍保存当前文档；编辑器事务更新当前文档的 `editorState` 和 `dirty`。关闭窗口时仍检查当前文档是否 dirty，并沿用现有退出确认行为。

### 编辑器

编辑器以当前文档路径作为文档身份。路径改变时销毁旧 `EditorView` 并以新文档的 `EditorState` 创建视图；事务直接更新当前文档，不再通过标签 ID 定位状态。

### 大纲与状态栏

大纲和字数统计直接从当前文档的 `editorState.doc` 派生。不存在当前文档时，大纲为空、字数为零。

### 窗口标题栏

BrowserWindow 使用隐藏标题文本但保留原生窗口控制按钮的 overlay 模式。渲染层标题组件固定在窗口内容坐标的最顶部，并预留原生窗口按钮安全区域；标题相对整个窗口水平居中，而不是相对编辑主区域或侧栏后的剩余空间居中。

标题组件占用窗口标题栏 overlay 的高度，不作为编辑页面布局中的额外一行。侧栏和编辑主区从标题栏下方开始，移除当前 `.app-layout` 中单独为 `DocumentHeader` 创建的 38px 内容网格行。

渲染层在当前文档变化时同步更新 `document.title`，使任务栏、辅助功能和系统窗口列表使用相同标题。主题切换时，主进程同步更新 `BrowserWindow.setTitleBarOverlay` 的 `color` 与 `symbolColor`。

### 标签栏清理

- 从应用布局中移除 `TabBar`。
- 删除标签栏组件及只服务于标签的样式。
- 删除 `setActive`、`closeTab` 等多标签专用操作。
- 更新代码注释和项目说明中与运行时多标签行为直接相关的描述；历史设计与实施记录不回写。

## 文件树语义

左侧文件树是可打开文件的集合，不代表这些文件已同时加载。拖入多个 Markdown 文件后，文件树可以展示多个条目，但 Store 中仍只有一个当前文档。

若拖入的多个文件来自不同目录，使用现有主进程 `openDropped` 返回的文件树结构作为展示依据；如现有返回结构无法表达所有文件，则在主进程中扩展为一个适合展示的临时文件集合，但不引入多文档编辑状态。

## 错误处理

- 自动保存失败：提示“自动保存失败，请手动保存后再进行操作”，不读取目标文件，不替换当前状态。
- 目标文件读取失败：沿用现有错误传播方式；若当前文档已自动保存，仍保留当前文档，不用空状态替换。
- 手动保存失败：继续显示现有的具体保存失败提示。
- 自动保存与打开流程按顺序执行，避免快速连续操作导致旧请求覆盖新文档。

## 验证范围

- 顶部标签栏完全消失，编辑区向上填充原有空间。
- 通过文件树连续打开两个文件时，第二次打开会替换当前文档。
- dirty 文档切换前自动保存，保存内容正确且新文件成功打开。
- 模拟保存失败时显示指定提示，当前内容、路径和编辑状态保持不变。
- 再次点击当前文件不重复加载或保存。
- 拖入多个 Markdown 文件后，左侧显示全部文件且只打开第一个。
- 系统窗口标题栏区域居中显示当前文件名；空状态显示 `Lume`，长文件名正确省略且不覆盖窗口按钮。
- 标题栏空白处可拖动窗口，原生最小化、最大化和关闭按钮可用。
- 侧栏和编辑区没有额外的页面内标题行，编辑区恢复对应空间。
- 深浅主题切换后标题栏 overlay 颜色与当前主题匹配。
- 大纲与字数统计始终对应当前文档。
- `Ctrl/Cmd+S`、菜单打开文件/文件夹、退出 dirty 确认仍可用。
- TypeScript 类型检查、ESLint 和生产构建通过。

## 非目标

- 不增加最近打开文件列表。
- 不保留后台文档、标签历史或文档切换缓存。
- 不改变 Markdown 解析、序列化和编辑交互。
- 不改变历史规格文档和实施计划中对当时多标签架构的记录。
