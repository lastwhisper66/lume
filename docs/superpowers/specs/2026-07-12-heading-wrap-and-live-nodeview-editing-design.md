# 标题自动换行与 NodeView 实时编辑设计

## 背景

标题 NodeView 当前在点击后使用 `input[type="text"]` 展示完整 ATX Markdown 源码。原生单行输入框不会换行，因此长标题进入编辑态后会横向滚动，破坏渲染态与编辑态之间的布局连续性。

标题和图片 URL 的临时输入框还只在失焦时把修改写回 ProseMirror。用户在输入框仍聚焦时按 `Ctrl+S`，文件保存逻辑会序列化旧的 ProseMirror 文档，可能遗漏屏幕上已经输入的内容。

本文档更新并取代 `2026-07-11-heading-source-edit-design.md` 中关于标题提交时机、Enter 和 Escape 的设计。标题源码可见、可编辑以及删除标题标记后转换为段落的既有能力继续保留。

## 目标

- 长标题进入源码编辑态后按编辑区宽度自动软换行，不产生水平滚动。
- 标题编辑实时写入 ProseMirror，确保撤销、dirty 状态和文件保存看到最新内容。
- 标题中的 Enter 执行文档结构编辑，而不是确认或保存操作。
- 图片 URL 编辑同样实时同步，避免聚焦期间保存旧值。
- 不改变普通段落、列表、引用、代码块及其他 Markdown 节点的既有编辑行为。

## 非目标

- 不在 Markdown 标题内部插入真实换行符。
- 不改变文件自动保存策略或 `Ctrl+S` 的文件写入流程。
- 不把图片 URL 改为多行字段。
- 不重构全部 NodeView 或 Markdown 解析架构。

## 交互设计

### 标题

- 未编辑时，标题继续渲染为 `h1` 至 `h6`。
- 点击标题后显示包含 `# ` 前缀的 ATX Markdown 源码。
- 源码编辑控件随内容自动增高，并使用软换行；软换行只影响显示，不写入 Markdown。
- 点击标题以外的位置，或通过键盘将焦点移动到其他编辑块后，退出源码态并恢复渲染。
- 鼠标仅移出标题区域不会退出编辑，避免打断选择文字、移动光标等操作。
- Escape 不承担取消或退出功能。撤销统一使用 `Ctrl+Z`，重做使用现有的 `Ctrl+Y` 或 `Ctrl+Shift+Z`。
- 删除合法的标题标记后，沿用现有行为，把该块转换为普通段落。

### Enter 拆分

在标题源码编辑态按 Enter 时，以当前选区为边界拆分文档：

- 选区前的标题正文保留在原级别标题中。
- 选区中的内容被删除。
- 选区后的正文成为紧随标题的普通段落。
- 光标进入新段落开头。
- 整次拆分作为一个 ProseMirror 历史步骤记录，一次 `Ctrl+Z` 可以恢复拆分前的标题。

在标题末尾按 Enter 会创建空段落；在标题正文开头按 Enter 会留下空标题并把原正文移动到普通段落。标题标记本身不属于可拆分到普通段落的正文内容。

### 图片 URL

- 点击图片后继续显示单行 URL 输入框。
- 每次输入都实时更新图片节点的 `src` 属性及文档 dirty 状态。
- NodeView 接收到自身产生的节点更新时保持 URL 输入框与焦点，不提前恢复图片渲染。
- 点击输入框外部退出 URL 编辑态。
- Enter 可作为单行字段的“结束编辑”快捷键，但不表示文件已保存。

## 架构与数据流

### 标题 NodeView

标题源码编辑控件改为支持软换行的自动增高文本区域。其值仍由标题节点序列化得到，编辑控件只是节点的临时呈现，不成为独立的数据源。

每次输入后：

1. 读取当前 ATX 源码。
2. 解析出标题级别和正文内容。
3. 用单个 ProseMirror transaction 更新对应节点。
4. NodeView 的 `update` 接收新节点，并在仍处于编辑态时同步控件值、尺寸和选区，而不是销毁控件。
5. workspace store 收到新 EditorState，dirty 状态、`Ctrl+S` 和切换文件前的自动保存均可读取最新文档。

标题输入区拦截 `Ctrl+Z`、`Ctrl+Y` 和 `Ctrl+Shift+Z`，调用 ProseMirror 历史命令，避免浏览器输入框历史与编辑器历史分裂。历史更新返回 NodeView 后，编辑控件同步为撤销或重做后的节点内容。

Enter 不把换行写入文本区域，而是直接派发“替换原标题并插入普通段落”的 transaction。点击外部只切换显示状态，不再承担提交未同步数据的职责。

### 图片 NodeView

图片 URL 输入事件通过 `setNodeMarkup` 实时更新 `src`。NodeView 记录当前是否处于编辑态；`update` 在编辑态只更新内部节点引用和输入框值，在非编辑态更新图片元素。这样实时 transaction 不会导致输入框在第一个字符后消失。

## 保存与撤销语义

- 输入、Enter 拆分和图片 URL 修改属于编辑器文档变更，实时进入 ProseMirror 状态。
- `Ctrl+S` 只负责把当前 ProseMirror 文档序列化并写入文件。
- 失焦只负责从源码呈现切回渲染呈现。
- 标题软换行不属于文档变更，不影响 dirty 状态或序列化结果。
- 标题拆分应是单个历史事件；连续普通输入沿用 ProseMirror history 的相邻输入分组行为。

## 异常与边界处理

- NodeView 的位置在 transaction 前失效时，不派发更新，避免写入错误节点。
- 标题源码暂时不符合 `#{1,6} + 空格` 规则时，沿用既有规则转换为普通段落；转换后退出标题专用源码态，由 ProseMirror 接管普通段落。
- 自动增高尺寸以内容的 `scrollHeight` 为依据，并在节点更新、窗口宽度变化和主题字体变化后重新计算。
- URL 为空或暂时不可加载时仍保留用户输入和节点属性，不由 NodeView 擅自回滚。

## 其他格式审计

- 普通段落、列表和引用直接由 ProseMirror 编辑，Enter 已执行正常的块拆分。
- 代码块由 CodeMirror 管理，Enter 已插入代码换行，`Mod-Enter` 用于退出代码块。
- 图片 URL 是唯一另一个临时单行输入字段，需要实时同步修复，但无需软换行。
- 当前未发现其他使用临时输入框并把 Enter 绑定为正文“提交”的格式。

## 验证方案

### 自动测试

- H1 至 H6 的长标题进入编辑态后使用可软换行控件。
- 自动增高逻辑不会产生水平滚动，并能在内容缩短后收缩。
- 标题中间按 Enter 生成“原级别标题 + 普通段落”，文本顺序和选区正确。
- 标题开头、末尾以及存在选区时按 Enter 的结果正确。
- Enter 拆分后一次撤销恢复原标题，一次重做重新拆分。
- 标题输入 transaction 后，EditorState 立即包含新内容。
- 图片 URL 输入 transaction 后，节点 `src` 和 workspace dirty 状态立即更新，输入框保持编辑态。

### 手工验证

- 在窄窗口编辑中英文混合的长 H1 至 H6，确认软换行、自动高度和点击位置光标准确。
- 标题仍聚焦时按 `Ctrl+S`，重新打开文件确认保存的是最新标题。
- 图片 URL 仍聚焦时按 `Ctrl+S`，重新打开文件确认保存的是最新 URL。
- 点击其他块后标题恢复渲染；仅移动鼠标离开标题不退出编辑。
- 普通段落、列表、引用、代码块、图片渲染和 Markdown 往返序列化无回归。
